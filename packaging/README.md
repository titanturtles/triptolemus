# Packaging — double-click executables

Two apps are packaged with PyInstaller (one file each, no Python needed to run):

- **`scoreboard_manager`** — the Cisco Scoreboard Manager (test creator).
- **`pt_agent`** — the student competition agent.

`pka_tool` is a separate Go binary already cross-built for every OS (in `pka_tool/`).

**PyInstaller cannot cross-compile** — build the Windows `.exe` on Windows, the
macOS build on macOS, the Linux build on Linux.

## Build
- **Windows:** run `packaging\build.bat` → `dist\pt_agent.exe`, `dist\scoreboard_manager.exe`
- **Linux / macOS:** `bash packaging/build.sh` → `dist/pt_agent`, `dist/scoreboard_manager`

Prebuilt **Linux/amd64** binaries are checked in at the project root:
`pt_agent_linux_amd64`, `scoreboard_manager_linux_amd64`.

If your system pip is "externally managed", build inside a venv:
```
python3 -m venv --system-site-packages .buildenv
. .buildenv/bin/activate        # Windows: .buildenv\Scripts\activate
pip install pyinstaller cryptography
bash packaging/build.sh         # or build.bat on Windows
```

## Distribute
- **Test creator** gets one folder: the `scoreboard_manager` executable **+ the
  `pka_tool/` folder beside it** (the manager calls `pka_tool` to read activity
  hashes). Its `manager_data/` (saved settings + per-competition configs) is
  created next to the executable.
- **Students** get one folder: the `pt_agent` executable **+ `pt_agent.conf.json`**
  (generated by the manager for that competition). First run per machine, they
  register `ptagent.pta` in Packet Tracer (Extensions → IPC → Configure Apps →
  Add, then quit PT normally).

Students never get `pka_tool` or the level `.pka` files — the server releases
levels and the manager/`pka_tool` stay on the instructor side.
